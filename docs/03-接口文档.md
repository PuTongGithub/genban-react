# 接口文档

## 基础信息

- **Base URL**: `/api`
- **数据格式**: JSON
- **字符编码**: UTF-8

---

## 接口列表

### 1. 获取模型列表

获取可用的 AI 模型列表。

**请求**

```
GET /api/get_models
```

**响应**

```json
["model-1", "model-2", "model-3"]
```

| 字段 | 类型 | 说明 |
|------|------|------|
| - | `string[]` | 模型名称数组 |

---

### 2. 创建新会话

创建一个新的对话会话，返回会话 ID。

**请求**

```
GET /api/new_session
```

**响应**

```json
"session-uuid-string"
```

| 字段 | 类型 | 说明 |
|------|------|------|
| - | `string` | 会话 ID |

---

### 3. 发送消息（流式）

发送用户消息并获取 AI 流式响应。

**请求**

```
POST /api/talk
Content-Type: application/json
```

**请求体**

```json
{
  "sessionId": "session-uuid-string",
  "userInput": "你好，请介绍一下自己",
  "model": "model-1"
}
```

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| session_id | `string` | 是 | 会话 ID |
| user_input | `string` | 是 | 用户输入内容 |
| model | `string` | 是 | 选择的模型名称 |

**响应**

响应采用 SSE (Server-Sent Events) 格式，`Content-Type: text/event-stream`。

**事件类型**

| 事件 | 说明 |
|------|------|
| `message` | 流式返回 AI 回答内容，每次返回全量 |
| `complete` | 回答完成，流式响应结束 |
| `error` | 发生错误时触发 |

**message 事件数据格式**

```json
{"role": "assistant", "content": "回答内容", "reasoning_content": "思考过程"}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| role | `string` | 消息角色，固定为 `"assistant"` |
| content | `string` | AI 回答内容（全量，每次返回完整内容） |
| reasoning_content | `string` | AI 思考过程（全量，每次返回完整内容） |

**error 事件数据格式**

```json
{"error": "错误描述信息"}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| error | `string` | 错误描述 |

**响应示例**

```
event: message
data: {"role": "assistant", "content": "", "reasoning_content": "让我"}

event: message
data: {"role": "assistant", "content": "", "reasoning_content": "让我思考"}

event: message
data: {"role": "assistant", "content": "", "reasoning_content": "让我思考一下..."}

event: message
data: {"role": "assistant", "content": "你好", "reasoning_content": "让我思考一下..."}

event: message
data: {"role": "assistant", "content": "你好！", "reasoning_content": "让我思考一下..."}

event: complete
data: 
```

**注意事项**

- 每次 `message` 事件返回的 `content` 和 `reasoning_content` 都是**全量内容**，前端直接替换显示即可，无需拼接
- 通过 `complete` 事件判断流式响应结束
- 需要监听 `error` 事件处理异常情况

---

## 错误处理

| HTTP 状态码 | 说明 |
|-------------|------|
| 200 | 成功 |
| 400 | 请求参数错误 |
| 500 | 服务器内部错误 |

流式响应中的错误通过 `error` 事件返回。
